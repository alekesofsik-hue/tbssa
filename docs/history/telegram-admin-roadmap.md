# История: Telegram admin roadmap

Этот документ заменяет старый детальный `ADMIN_ROADMAP.md` и фиксирует результат в сжатом виде.

## Что было целью

Внутри Telegram нужно было построить полноценную административную панель поверх базы данных и `ConfigService`, без ручного редактирования `.env` для повседневной эксплуатации.

## Что в итоге было реализовано

- база данных и миграции;
- `ConfigService` как runtime-источник конфигурации;
- `/admin` с fail-closed защитой;
- CRUD серверов;
- CRUD пользователей;
- редактирование настроек без перезапуска;
- аудит действий;
- мультисерверный режим команд.

## Крупные этапы

### Sprint 0

- подготовлены БД, Alembic, seed и `ConfigService`.

### Sprint 1

- реализованы `/admin`, главное меню и защита доступа.

### Sprint 2

- реализовано управление серверами через Telegram.

### Sprint 3

- реализовано управление администраторами через Telegram.

### Sprint 4

- параметры проекта перенесены из `.env` в editable config через admin UI.

### Sprint 5

- добавлен журнал действий и базовая наблюдаемость.

### Sprint 6

- команды переведены с одиночного сервера на список серверов.

## Примечание

Этот файл хранится как историческая справка. Актуальная архитектура проекта уже не Telegram-centric: эксплуатационный контур общий для Telegram и MAX.
