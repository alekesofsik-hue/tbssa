# ADMIN_ROADMAP — Telegram Admin Interface

Дорожная карта реализации системы администрирования внутри Telegram-бота (Вариант B).

---

## Обзор архитектуры

```
┌─────────────────────────────────────────────────────┐
│                  Telegram Bot                       │
│                                                     │
│  Handlers         ConfigService      Database       │
│  ─────────        ─────────────      ────────       │
│  /status     ───► get_servers()  ───► servers       │
│  /reboot     ───► is_admin()     ───► users         │
│  /admin      ───► get_global()   ───► config        │
│                   reload()                          │
└─────────────────────────────────────────────────────┘
```

---

## Спринт 0 — Подготовка инфраструктуры

**Цель:** Заложить фундамент: БД, миграции, ConfigService. Без этого спринта ничего не работает.

### Зависимости

- [x] Добавить в `pyproject.toml` зависимости:
  - `sqlalchemy>=2.0` (async ORM)
  - `aiosqlite` (async SQLite driver)
  - `alembic` (миграции)

### Модели БД

- [x] Создать `src/tbssa/db/models.py`:
  - Таблица `users` — `id`, `telegram_id` (UNIQUE), `username`, `first_name`, `is_active`, `created_at`
  - Таблица `servers` — `id`, `name`, `ssh_host`, `ssh_user`, `ssh_key_path`, `ssh_known_hosts`, `ssh_fingerprint`, `ping_host`, `is_active`, `created_at`
  - Таблица `config` — `key` (PK), `value`, `updated_at`
  - Таблица `audit_log` — `id`, `telegram_id`, `username`, `action`, `details`, `created_at`
- [x] Создать `src/tbssa/db/engine.py` — инициализация async engine и sessionmaker

### Миграции

- [x] Инициализировать Alembic (`alembic init alembic/`)
- [x] Настроить `alembic/env.py` для async SQLAlchemy
- [x] Создать начальную миграцию (`alembic revision --autogenerate -m "init"`)
- [x] Проверить применение миграции (`alembic upgrade head`)

### ConfigService

- [x] Создать `src/tbssa/config_service.py`:
  - In-memory хранение: `_servers: list[Server]`, `_config: dict[str, str]`, `_admin_ids: set[int]`

  - Метод `get_servers()` — список активных серверов

### Интеграция в точку входа

### Definition of Done ✓

> - Бот запускается, читает конфиг из БД, команды `/status` `/reboot` `/sos` работают как раньше

## Спринт 2 — Управление серверами

**Цель:** Полноценный CRUD серверов через Telegram.

### Список серверов

- [x] Кнопка «🖥 Серверы» → список серверов с inline-кнопками:
  ```
  🟢 windows-home   [Подробнее] [Откл.]
  🔴 dev-server     [Подробнее] [Вкл.]
  ─────────────────────────────────────
  [➕ Добавить сервер]
  ```
  - Иконка 🟢/🔴 = `is_active`

### Просмотр сервера

- [x] Кнопка «Подробнее» → карточка сервера:
  ```
  🖥 windows-home

  SSH: bot-admin@100.114.138.122
  Ключ: ~/.ssh/id_ed25519_bot
  Ping host: 100.114.138.122
  Статус: Активен

  [✏️ Редактировать] [🗑 Удалить] [◀️ Назад]
  ```

### Добавление сервера (FSM / ConversationHandler)

- [x] Кнопка «➕ Добавить сервер» → пошаговый диалог:
  - Шаг 1: Введите `name`
  - Шаг 2: Введите `ssh_host`
  - Шаг 3: Введите `ssh_user` (Enter для дефолта `bot-admin`)
  - Шаг 4: Введите `ssh_key_path`
  - Шаг 5: Введите `ping_host` (Enter = то же что `ssh_host`)
  - Финал: подтверждение «Всё верно? [✅ Сохранить] [❌ Отмена]»
- [x] Валидация на каждом шаге (не пустая строка, корректный формат IP/hostname)
- [x] Команда `/cancel` выходит из диалога в любой момент

### Редактирование сервера

- [x] Кнопка «✏️ Редактировать» → меню полей:
  ```
  Что изменить?
  [SSH host] [SSH user] [Ключ]
  [Ping host] [Fingerprint]
  [◀️ Назад]
  ```
- [x] Выбор поля → бот просит ввести новое значение → сохраняет, вызывает `config_service.reload()`

### Удаление / деактивация

- [x] «🗑 Удалить» → подтверждение «Вы уверены? Это нельзя отменить. [✅ Да] [❌ Нет]»
- [x] Реализовать мягкое удаление (`is_active = False`) — данные не теряются
- [x] Хард-удаление — только если явно нет связанных данных

### Аудит

- [x] Все операции (добавление, редактирование, удаление) пишутся в `audit_log`

### Definition of Done ✓

> - Можно добавить новый сервер через бота и сразу выполнить `/status` на нём
> - Изменение `ssh_host` применяется мгновенно без перезапуска бота
> - Деактивированные серверы не появляются в командах

## Принципы безопасности на каждом этапе

- **Токен бота** — только в `.env`, никогда в БД и в сообщениях бота
- **SSH-ключи** — только пути в БД, файлы не передаются и не отображаются
- **fail-closed** — если `config_service` не загрузился, бот не принимает admin-команды
- **Аудит с первого дня** — `audit_log` пишется начиная со Спринта 0 (для команд) и Спринта 1 (для /admin)
- **Подтверждение опасных операций** — `/reboot`, `/sos`, удаление сервера/пользователя требуют явного подтверждения
- **Защита последнего пользователя** — нельзя удалить/деактивировать себя, если ты единственный активный админ
- **Таймаут сессии** — неактивное меню /admin закрывается через 5 минут
- **Namespace callback_data** — все admin callback начинаются с `adm:`, чтобы исключить коллизии
